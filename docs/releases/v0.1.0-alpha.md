# v0.1.0-alpha — SQLite and GPU decay fitting

First experimental source release of nuclideid for Linux x86-64. It fits
positive single-exponential decay measurements and reports compatible isotope
candidates. It does not establish a unique physical isotope identity.

## Included

- GNU x86-64 assembly host tools and NVIDIA PTX kernels.
- Verified HTTPS isotope downloader and transactional SQLite importer.
- Committed `isotopes.sqlite3`: 3,386 nuclides; 2,797 unqualified measured
  records participate in candidate matching. The IAEA snapshot reports an
  extraction date of 2023-10-18.
- Direct SQLite-to-memory loading, with no isotope `.bin` intermediary.
- GPU fitting over every measurement, plus an explicit `--cpu` reference mode.
- Synthetic CSV generator, five guided teaching datasets and seven experiments.
- Original Silver-111 research archive, attribution, checksums, derived inputs,
  preparation scripts, source discrepancy audit, and CPU/GPU output records.
- Original-file backups and build, usage, model and validation documentation.

## Strengths

- Double-precision fitting with time normalization and centered regression;
  handles varying amplitude and a wide tested range of decay constants.
- Checks measurement types, finite values, increasing times and positive
  intensities. Rejects invalid data, poor fits and absent matches explicitly.
- Uses the actual SQLite record count and lists all candidates within a stated
  relative decay-constant tolerance, including ambiguous results.
- Separates stable, unknown, qualified and measured half-lives. Failed imports
  preserve the previous database; the inference catalog is opened read-only.
- Checked CUDA operations and cleanup. GPU failures remain errors; there is
  no silent CPU fallback.
- Reproducible CPU/GPU comparisons against independent Python calculations and
  real measurement data, rather than synthetic generator output alone.

## Weaknesses and limits

- The model is `y=A*exp(-k*t)` with least squares in log space. It is not a
  Poisson count likelihood and does not fit background, mixtures, daughter
  ingrowth or detector response. Zero/negative intensities are rejected.
  Some mixtures/backgrounds may still resemble a single exponential and pass.
- No propagation of measurement or reference half-life uncertainty. The default
  1% matching tolerance and log RMSE/R-squared gates are engineering settings,
  not confidence levels. Similar half-lives can give several candidates.
- Ground states only; metastable nuclear states are not represented. Stable,
  unknown and qualified half-lives are excluded from matching.
- Real-data validation currently covers one isotope (Ag-111), measured with two
  detectors. Results of 7.43342 and 7.42645 days include Ag-111 as the sole
  default-tolerance candidate, but do not reproduce the workbook's corrected
  7.42360 +/- 0.00112-day precision. The source archive contains 39 OR50
  workbook/report peak-area differences and one abbreviated filename; those
  discrepancies are retained and documented, not silently reconciled.
- Linux x86-64 host code. Hardware testing used a GTX 1060 6GB, compute 6.1.
  GPU fitting uses one block of 256 threads; no throughput advantage over CPU
  is claimed. The default CUBIN target is `sm_61`; changing GPU architecture
  requires a kernel/host rebuild.
- Generation and inference still require the CUDA toolkit/driver library at
  build/link time, including for explicit CPU reference mode.
- NVIDIA Compute Sanitizer 2022.3 could not instrument this environment.
  Successful memory/synchronization sanitizer results are not claimed.
- Alpha CLI, schema and model behavior may change. This release provides source
  and data; it does not provide portable prebuilt executables or a macOS app.

## Validation

66 integration/regression tests passed across the importer (16), catalog (15),
decay pipeline (27), and retained real dataset (8). Hardware cases ran on the
GTX 1060. The 27 decay tests passed in debug and release builds. All seven guided
experiments also produced their expected outcomes on both CPU and GPU.
Examples with background, mixtures and a zero count intentionally demonstrate
rejection rather than a supported fit for those models.

## Quick start

Requires GNU binutils, GCC/libc development files, libsqlite3-dev, libcurl,
CUDA ptxas and the NVIDIA driver library. See the stage READMEs for details.
The committed SQLite database is ready to use; initial downloading is optional.

```sh
make release
./release/bin/x86_64/learn_decay/learn_decay datasets/ag111/derived/or20.csv isotopes.sqlite3
# Explicit CPU reference mode:
./release/bin/x86_64/learn_decay/learn_decay datasets/ag111/derived/or20.csv isotopes.sqlite3 --cpu
# Guided experiments, including intentionally rejected inputs:
python3 examples/experiments/run.py
python3 examples/experiments/run.py --gpu
```

Start with `examples/experiments/README.md`. Detailed results and model limits
are in `docs/decay-validation.md`, `datasets/ag111/README.md` and
`x86_64/learn_decay/README.md`.
